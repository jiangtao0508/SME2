# Linux现场实验操作清单

## 1. 本次目标

现场先不修改对方编译器和IR，完成四件事：

1. 确认 pytest、FlagGems、Triton和指定编译器的真实版本与路径。
2. 确认 BMM 测试从 Python 到机器码的实际文件链。
3. 确认 SME 首次出现在哪一层，最终二进制是否真的包含 SME 指令。
4. 把测试时间、冷/热缓存差异、文件哈希和待确认问题保存成报告。

## 2. 克隆后自检

```bash
git clone https://github.com/jiangtao0508/SME2.git
cd SME2
python3 --version
bash scripts/check_layout.sh
bash scripts/run_onsite_selftest.sh
bash scripts/run_onsite_analysis.sh --help
```

如对方 pytest 必须使用特定 Python：

```bash
export PYTHON_BIN=/path/to/their/python
"$PYTHON_BIN" -m pytest --version
```

## 3. 先手工复现一次

在对方要求的环境中执行原始命令，不先加入我们的优化：

```bash
cd /path/to/FlagGems
pytest -s \
  'test/test_blas_ops_mem.py::test_accuracy_bmm_membound[dtype2-8192-64-2048]'
```

记录：

```text
命令是否成功
pytest打印的时间
dumps真实绝对路径
cache真实绝对路径
是否第一次运行
第二次运行是否复用cache
```

## 4. 分析现有dump

```bash
cd /path/to/SME2
bash scripts/run_onsite_analysis.sh \
  --dump /absolute/path/to/dumps \
  --case-name bmm_8192_64_2048 \
  --test-workdir /absolute/path/to/FlagGems \
  --test-command "pytest -s 'test/test_blas_ops_mem.py::test_accuracy_bmm_membound[dtype2-8192-64-2048]'"
```

这一命令只记录测试命令，不重新执行 pytest。

## 5. 让工具执行并计时

确认命令无误后再加 `--run-test`：

```bash
bash scripts/run_onsite_analysis.sh \
  --dump /absolute/path/to/dumps \
  --case-name bmm_8192_64_2048_hot \
  --test-workdir /absolute/path/to/FlagGems \
  --test-command "pytest -s 'test/test_blas_ops_mem.py::test_accuracy_bmm_membound[dtype2-8192-64-2048]'" \
  --run-test
```

注意：这里记录的是完整 pytest 墙钟时间，可能包含 Python、JIT、正确性检查和缓存。
算子内核时间必须从 pytest 自身输出或现场计时接口单独确认。

## 6. 首先查看这些文件

```bash
cd onsite_results/<本次用例目录>
less ONSITE_REPORT_CN.md
less 04_ir_transitions.md
less 05_sme_evidence.txt
column -s, -t 02_artifact_inventory.csv | less -S
```

重点确认：

```text
00_input.mlir中是什么高层语义
01_after_transform_interpreter.mlir增加了哪些循环/向量操作
03_after_convert_to_llvm.mlir是否出现arm_sme或LLVM SME
ll.ir/ll.mlir里是否还有SME intrinsic
kernel.o、bmm_kernel.obj、launcher.so分别包含哪些指令和符号
```

## 7. 必须向对方确认

1. dump由哪个环境变量、pytest插件或编译器参数打开？
2. 编号文件对应的准确Pass名称和命令行是什么？
3. `kernel.o`和cache中的`bmm_kernel.obj`是否内容相同？
4. `_cpu_kernel_launcher.so`是纯launcher还是包含计算内核？
5. 计时是JIT时间、端到端时间还是kernel时间？
6. 第一次与第二次运行分别命中哪些cache？
7. 是否允许使用`perf stat`或其他PMU工具？
8. 是否可以把我们的Transform插件加载到对方`mlir-opt`，ABI是否一致？

## 8. 数据带出边界

默认报告包不复制完整源码或IR，只保存：

```text
环境与版本
测试日志
相对路径、文件大小与SHA256
操作/指令计数
层间差分
readelf/nm/objdump派生结果
不含源码片段的启发式摘要
```

是否允许带出测试日志和反汇编仍应遵守对方现场规定。必要时使用
`--no-package`，只在对方机器上阅读结果。
